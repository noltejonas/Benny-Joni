P0 — Sofort fixen (Datenverlust / komplett broken)

Diese Bugs führen zu silently falschen Daten oder brechen komplette Features.

🔴 BUGCRITICAL History ignoriert Work-Sessions komplett screens.jsx
Lines 1677, 1767, 1786, 2405 — HistoryScreen + StatsChart + computeAthleteStats
Alle Aggregationen summieren s.reps — bei Work-Sessions ist das null, ergibt 0. Work-Wochen erscheinen leer im Chart, "Erster zum Ziel"-Badge immer "–", Stats-Totals ignorieren geleistete Minuten.
Überall s.reps → (s.reps ?? s.duration_minutes ?? 0) ersetzen. Benötigt category-kind-Lookup für korrekte Einheit.
🔴 BUGCRITICAL weekRecaps in app.jsx: NaN-Totals bei Work-Challenges app.jsx
Lines 127–128, 160 — weekRecaps useMemo
reduce((a,x) => a+x.reps, 0) addiert null → 0, aber bennyMaxSet = Math.max(m, null) = 0. Wochenabschluss-Recap zeigt "0 Reps Vorsprung" auch wenn 10h geloggt wurden. Analysis-Text sagt stets "Reps Vorsprung".
Für Work-Challenges duration_minutes summieren, isWorkCh-Flag aus catById ableiten. Analysis-String einheits-abhängig machen.
🔴 BUGCRITICAL onQuickLog schickt reps für Work-Challenges app.jsx
Lines 431–437 — HomeScreen onQuickLog handler
QuickLog ist für alle Challenges sichtbar, sendet aber immer reps: parseInt(v) — bei Work-Challenges müsste es duration_minutes sein. Führt zu Datenverfälschung.
Category-Kind prüfen; Work-Challenges: { duration_minutes: parseInt(v) } senden, Toast anpassen. Oder QuickLog für Work-Tab deaktivieren.
🔴 BUGCRITICAL Penalty-System bricht für Work-Challenges data.js
Lines 63–90, 94–135 — repsForAthleteOnChallenge + computePenalties
repsForAthleteOnChallenge() summiert s.reps → 0 für alle Work-Sets. Work-Challenges werden immer als "nicht erfüllt" gewertet, egal wie viele Stunden geloggt wurden. Penalty-Reason sagt "120 Reps unter fairShare" statt Minuten.
In computePenalties() pro Challenge prüfen ob kind === 'work'; dann duration_minutes summieren. Reason-Strings einheits-abhängig.
🔴 BUGCRITICAL repsOnLocalDate() und dailyBreakdownFor() ignorieren duration_minutes screens.jsx
Lines 105–109, 113–138 — Hilfsfunktionen für DailyStatus
Tages-Tracking-Anzeige zeigt immer 0 für Work-Sessions. "Heute X / Tagesziel" im Tug-Card zeigt falsches Ergebnis für Work-Challenges.
(s.reps ?? s.duration_minutes ?? 0) überall wo Sets summiert werden.

🔴 BUG Fehlende Performance-Indexes in Migrations migrations
supabase/migrations/ — alle Dateien

Migration 20260513030000_indexes.sql anlegen mit CREATE INDEX IF NOT EXISTS sets_project_tag_id_idx ON sets(project_tag_id) etc.
🔴 BUG ON CONFLICT DO NOTHING ohne UNIQUE-Constraint migrations
20260513000000_work_tags.sql — Lines 34–44
INSERT ... ON CONFLICT DO NOTHING funktioniert nur wenn eine UNIQUE-Constraint existiert. Ohne diese schlägt der Conflict-Check fehl und Seeds werden bei Re-Run dupliziert.
CREATE UNIQUE INDEX IF NOT EXISTS project_tags_name_idx ON project_tags(name); vor den INSERTs. Dann ON CONFLICT (name) DO NOTHING.
